Ranking Refresh Candidates: A Content Opportunity Score for Search Visibility

Umemah Naveed· FlyRank AI Internship, July 2026 cohort· Machine Learning Track
Abstract

Content teams can only review a handful of pages a week, so the question is which ones to look at first. This paper asks whether observable search signals — visibility, position, engagement — can rank pages for refresh review better than a simple hand-written rule. Using a 30,000-row anonymized slice of real FlyRank search data, I built a decision-tree classifier validated on a client-holdout split, and compared it against a transparent baseline built only from position and click-through rate. The model outperformed the baseline: Precision@20 of 0.80 versus 0.70, and Precision@50 of 0.68 versus 0.64. The result is a ranked, explainable review queue — not a guarantee that refreshing any single page will recover its traffic.

01

Introduction

Every content team eventually runs into the same limit: dozens of pages might be worth a second look this month, but only a handful can actually get one. Somebody has to decide which pages come first, and right now that decision usually rests on gut feel or a hand-written rule of thumb.

This project asks a narrower, answerable version of that problem: given only signals that were knowable before any decision was made about a page, can we rank pages for refresh review better than a simple fixed rule? The decision this supports is a content reviewer's queue — not an automatic edit, not a guarantee of recovery, just a better-ordered list of where to look first.

02

Data

This work uses the starter release that ships with the FlyRank ML Internship: a 30,000-row anonymized slice of real search performance data (content_refresh_anonymized.csv), one row per content page. Rows were kept only when a page had real visibility and enough history to judge:

90d+minimum content age
>0minimum 90-day impressions
6features used

Pages younger than 90 days were excluded because there isn't yet enough history to call a trend a decline. Pages with zero impressions were excluded because the ranking signals (CTR, average position) are undefined without any visibility — those pages are a discoverability problem, not a refresh problem.

Public-safe by design: every identifier in this dataset is pseudonymized. No client names, domains, raw URLs, or query text appear anywhere in this paper or the underlying repository.

03

Methodology

Label

The target is trend_direction == "down" — a proxy, not a true future outcome, since it's computed from the same window as the features. This is a known limitation, addressed openly in Section 5.

Features

Six signals, each knowable at the moment a reviewer would look at the page: impressions_90d, content_age_days, avg_position, ctr, sessions_90d, word_count.

Baseline

An early version of the baseline scored a suspicious 1.000 precision — a signal that something was wrong, not that the rule was excellent. It had been built using the decline label itself as an input, which meant it wasn't predicting anything; it was reading the answer key. That version was discarded. The honest baseline used in this paper is built only from avg_position and ctr, with no reference to the label it's trying to rank against.

Model & validation

A depth-4 decision tree classifier, trained with class weighting for the label imbalance. Validation uses a client-holdout split — entire clients are held out of training and only appear in the test set — so the model is scored on clients it has genuinely never seen, not just unseen pages from familiar clients.

05

Limitations & Honest Framing

What this paper does not claim

This is decision-support, not proof. The results are observed and directional — they describe association within this data slice, not causation. Refreshing a flagged page is not guaranteed to recover its traffic; testing that would require a controlled experiment this data cannot provide.

  • The label is a same-window proxy for decline, not a verified future outcome.
  • This uses a 30,000-row anonymized starter slice, not the full ~79M-row warehouse — findings may not generalize to all clients or time periods.
  • No causal or algorithmic claims are made about how Google ranks pages.
